3PL运营平台静态原型

本原型分为平台端与货主端两部分：平台端供 3PL 运营方内部用户使用（用户中心单点登录），货主端为入驻货主门户（用户中心账号，用户与权限由用户中心承载、3PL 经接口代管不留痕，见需求 11.2）。聚焦客户要货、配送、入库、退仓、库存、审批和异常处理场景，并新增大小包装转换（大小码转换）全链路页面，对齐徐福记试点业务规则，可作为产品评审、UI深化和前后端协作的起点版本。

范围：3PL平台
终端：平台端 + 货主端（PC Web）
页面：平台端 43 页（工作台 / 基础配置 / 业务中心 / 大小码转换 / 库存与协同）+ 货主门户 15 页（基础数据 6 页支持货主自维护增删改查）
大小码转换：按明细命中大小码对应关系表判定，转换后商品必为对应小码、数量合计=要货数量

承运商与 TMS 触发规则（12.5.35 · V2.8 运输触发矩阵）
一期要货 / 退仓固定平台承运
V2.8：一期不做承运商类型选择，carrier_type 由系统按 service_type 固定写入、前端只读。客户要货发货 DEMAND 与退仓 WHS_RETURN 固定由平台服务商承运（= 2），审核有效且派生成功后即下发 API-12T / API-11T 到 TMS，API-14T 回传；入库 INBOUND 固定供应商自送、退厂 VENDOR_RETURN 固定供应商自提（= 1）不下发 TMS；LOC_CHANGE 为库内作业不涉及运输。二期开放全类型承运商选择与「仅 carrier_type = 2 且服务涉及运输才下发 TMS」的完整规则。
service_type是否涉及运输一期承运商（系统固定）平台服务商时的 TMS 指令一期行为 / 二期开放
DEMAND 配送是（仓 → 客户 / 门店）2 平台服务商承运API-12T 配送任务下发；API-14T 回传一期即触发：派生 KHYH 成功后下发 API-12T
INBOUND 入库是（供应商 → 仓）1 供应商自送API-11T 入库运输指令（RKYD）一期不触发；二期开放平台服务商后触发
WHS_RETURN 退仓是（客户 / 门店 → 仓）2 平台服务商承运API-11T 退仓提货指令；API-14T 回传一期即触发：派生 TCSQ 成功后下发 API-11T
VENDOR_RETURN 退厂是（仓 → 供应商）1 供应商自提API-12T 退厂运输任务一期不触发；二期开放平台服务商后触发
LOC_CHANGE 库存地点变更否（同仓库内移库）不适用不下发任何 TMS 指令一期仅下发 WMS 库内移库指令
TRANSFER 仓间调拨是（源仓 → 目标仓，双段）二期开放源仓 API-12T + 目标仓 API-11T二期开放：一期不建单、不派生、不下发
TRANSPORT_SERVICE 运输服务是二期开放二期设计（11.7 → TMS）二期开发
STOCK_COUNT 盘点计划否不适用不下发二期开发
INV_LOCK 库存锁定 / 释放否不适用不下发二期开发
VAS 增值服务视服务内容二期开放二期设计二期开发
TMS 指令与 WMS 指令解耦：下发失败重试 3 次告警转人工，不阻断 WMS 作业；幂等键 request_no + service_type + version，API-14T 按 transport_no + version 去重。一期不对接 BMS（R7）。
